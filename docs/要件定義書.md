# 要件定義書：選手向けフィジカル・モチベーション管理アプリ

## 1. 機能要件（画面ごとに整理）

### 1.1. 共通画面

* **ログイン画面**:

* 選手名と合言葉（パスワード）によるログイン機能。

* 権限（選手 or コーチ）に応じた画面へのリダイレクト。

### 1.2. 選手向け画面

* **選手ダッシュボード（ホーム画面）**:

* 自身の現在の出席率の表示。

* 直近の体重推移グラフの表示。

* 主要なフィジカル数値（Big3のMAX値）の表示。

* **データ入力画面**:

* 日次入力：当日の「出席/欠席」の選択、および「体重（kg）」の入力。

* フィジカル入力：定期測定するBig3（ベンチプレス、スクワット、デッドリフト）の数値入力。

### 1.3. コーチ・管理者向け画面

* **チームダッシュボード**:

* チーム全体の当日の出席状況一覧表示。

* 選手全員の体重推移一覧の確認。

* **フィジカルデータ管理画面**:

* 選手ごとのフィジカル測定結果（Big3など）の一覧表示。

* 数字を意識させるためのシンプルなランキング表示。

---

## 2. 非機能要件（REGAIN標準構成）

* **開発方式**:

* コーディングはAIエージェント（GenSpark）で実施。

* 人によるコード編集は行わない。

* **データベース**:

* GenSpark内蔵データベースを使用。

* **ホスティング**:

* GenSpark上でホスティング。

* **対応デバイス**:

* スマホ最適化（モバイルファースト）。

* PC・タブレットでも閲覧可能（レスポンシブ対応）。

* **セキュリティ・認証**:

* 認証方式: 選手名 + 合言葉（パスワード）。

* パスワードリセット: 管理者（コーチ）による手動リセット。

* 高度なセキュリティ機能は実装しない。

* **サンプルデータ投入**:

* プレビュー用として、初期状態から数名分の選手データやダミーの記録を投入しておく。

## 4. データ構造（保存するデータ）

必要最小限の構成とするため、以下の3つのテーブル（コレクション）で管理します。

### 4.1. Users（ユーザー情報）

* `id`: ユーザーID（一意）

* `name`: 氏名（ログインID兼用）

* `password`: 合言葉（パスワード）

* `role`: 権限（"player" または "coach"）

### 4.2. DailyRecords（日次データ）

* `id`: 記録ID

* `user_id`: ユーザーID（誰の記録か）

* `date`: 記録日

* `attendance`: 出欠状況（出席 / 欠席）

* `weight`: 体重（kg）

### 4.3. PhysicalRecords（フィジカルデータ）

* `id`: 記録ID

* `user_id`: ユーザーID

* `date`: 測定日

* `bench_press`: ベンチプレスの数値（kg）

* `squat`: スクワットの数値（kg）

* `deadlift`: デッドリフトの数値（kg）

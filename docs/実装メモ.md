# 実装メモ（要件定義書との対応・変更点）

要件定義書の内容をもとに、本番公開に向けて Vercel ＋ Supabase で実装した際の補足です。

## 1. 要件定義書からの変更点

| 項目 | 要件定義書 | 実装 | 理由 |
|---|---|---|---|
| 開発・DB・ホスティング | GenSpark | GitHub ＋ Vercel ＋ Supabase | 本番公開の方針変更（ユーザー指示） |
| 合言葉の最低文字数 | 指定なし | **6文字以上** | Supabase Auth の仕様（パスワードは6文字以上） |
| 合言葉の保存場所 | Users テーブルの `password` | **Supabase Auth が暗号化して保管** | 合言葉を読める形で保存しないため。Users テーブルには持たない |
| 選手の合言葉 | 選手名 ＋ 合言葉 | **選手は合言葉なし（名前を選ぶだけ）。合言葉はコーチのみ** | ユーザー指示。合言葉リセット機能も削除 |
| 選手の情報 | 名前のみ | **名前・学年・ポジション（フロント／バックロー／バックス）・並び順** | ユーザー指示 |
| サンプルデータ | 初期状態から投入 | 初期設定画面で「サンプル選手も入れる」を選ぶと投入 | 本番では不要になるため選べるようにした |

「選手管理」は、約30名の選手登録のために追加しました。

- 選手は「名前・学年・ポジション」で登録します（合言葉は不要）。コーチを追加するときだけ合言葉を入力します。
- 選手の並び順は、基本は学年が上の人が上。新しく追加した選手は「同じ学年の一番下」に入ります。
- 左の ⋮⋮ をつかんでドラッグ＆ドロップで自由に入れ替えでき（`@dnd-kit` を使用。スマホのタッチ操作にも対応、`components/SortableList.tsx`）、「学年順に並べ直す」で学年順に戻せます。ドロップした時点で自動保存します。絞り込み中は並び替えできません。
- この並び順はログイン画面・チーム画面・フィジカル画面の一覧でも使われます。

## 3. データ構造（要件定義書 4章に対応）

SQL は `supabase/schema.sql`。

- `users`：id / name（ログインID兼用）/ role（player・coach）/ login_email（内部用。メールは送らない）/ grade（学年。画面では1〜5年）/ position（PR・HO・LO・FL・No.8・SH・SO・CTB・WTB・FB。以前の区分「フロント・バックロー・バックス」も既存データ用に保存可）/ sort_order（並び順。小さいほど上）/ category（レギュラー・ベンチ・ベンチ外。未設定は null。変更はコーチのみ、サーバー側で確認）
- `daily_records`：id / user_id / date / attendance（出席・欠席）/ absence_reason（欠席理由：体調不良・学校関連・病院・リハビリ・冠婚葬祭・ずる休み・その他。欠席のときだけ入り、出席・オフのときは null）/ weight
- `physical_records`：id / user_id / date / bench_press / squat / deadlift
- `metrics`：id / key（weight=体重・bench_press・squat・deadlift・big3_total。今までの入力欄の値を使う項目の目印。普通の項目は空）/ name / unit / category（体組成・フィジカル）/ better（high=大きいほど良い・low=小さいほど良い）/ sort_order / show_ratio（true＝選手一覧・CSVで体重比も表示。初期値 false）
- `metric_records`：id / user_id / metric_id / date / value（項目ごとの記録）
- `training_records`：id / user_id / week_start（その週の月曜日）/ score（筋トレ遂行度 0〜10）
- `app_settings`：key / value（`training_criteria`＝筋トレ評価基準の説明文）
- `practice_days`：date（練習日。行がある日＝練習日）/ created_at。閲覧はメンバー、追加・削除はコーチのみ
- 同じ人・同じ日付（筋トレは同じ週）の記録は1件（再入力すると上書き）
- 追加分のSQLは `supabase/migrations/20261115_dashboard_items.sql`、`20261115_2_linked_metrics.sql`、`20261115_3_positions.sql`、`20261115_4_practice_days.sql`、`20261115_5_absence_reason.sql`、`20261115_6_player_category.sql`、`20261115_7_metric_show_ratio.sql`（`schema.sql` の末尾にも同じ内容）

### 計算方法

- 出欠席率（練習日ベース）：出席率＝練習日の出席日数 ÷ 練習日数、欠席率＝練習日の欠席日数 ÷ 練習日数（未入力は出席に含めない）
  - 今日より後の練習日と、その選手の登録日より前の日は数えない（登録より前の記録がある場合は最初の記録日から）
  - 練習日を1日も設定していない月は、今までどおり出欠を記録した日を対象に計算
  - オフの日（練習日を設定した月の、練習日ではない日）は計算に含めない。選手はオフの日は出欠を入力せず、体重だけ記録できる
  - 選手一覧の「出席率(今月)」、ダッシュボード「出欠席率」の月別表、選手ホーム・選手詳細の出席率はすべてこの計算
- 筋トレ遂行率：点数（0〜10）の平均を「9.0 / 10」の形で表示（% 表記は使わない）。入力のある週だけで平均（未入力の週は0点扱いしない）
  - コーチ「筋トレ遂行率」の選手ごとの表：直近8週
  - 選手ホーム『筋トレ遂行率』：今週 / 直近30日（この30日にかかる週）/ 全期間 を、自分とチーム平均（選手ごとの遂行率の平均）で比較。月別（0〜10）も
  - 月別：週の月曜日がその月に入る週の点数の平均（0〜10）。コーチ画面ではチーム・FW・BK平均と選手別
- 連続出席（選手ホーム）：出欠の対象日を新しい順にさかのぼって、出席が続いている回数（今日がまだ未入力なら今日は飛ばす）
- 選手ホームの体重推移の点線：自分の区分（FW / BK）の選手全員の、その日時点の最新体重の平均
- 選手一覧の指標の列は、`metrics`（項目設定）に登録された項目だけを、項目設定の並び順で表示（ほかに「出席率」「筋トレ」の列あり）。BMIなどアプリ側で計算する固定の列はない
- 体組成の平均カード（全体・FW・BK）は体重のみ（毎日の記録の体重）：選んだ日の時点で、各選手のその日以前の最新の記録を平均（記録のない選手は除外）。7日前比・30日前比は、その日数前の時点の平均との差。推移グラフも体重のみで、期間内の毎日について同じ方法で平均
- フィジカルの平均（全体・FW・BK）：選んだ日の時点で、各選手の「最新値」（その日以前の最新の記録）または「自己ベスト」（その日以前のベスト。Big3合計は種目ごとのベストの合計）を平均。体重比は、その記録の日の体重で割る。推移グラフは期間内の毎日について同じ方法で平均。ランキングも同じ基準・基準日
- 選手一覧：体組成は最新値、フィジカルは自己ベスト（項目の「良い向き」に合わせて最大／最小）
- 体重比（show_ratio が ON の項目）：選手一覧・CSVで、その項目のすぐ右に「項目名体重比」列。値 ÷ その記録日時点の体重（同じ日の体重 → なければその日以前で最新 → それもなければ最新の体重）、小数第2位。値・体重が無いか0なら「—」。表示している値（体組成＝最新値の記録日 / フィジカル＝自己ベストを最初に出した日。Big3合計は種目ごとの自己ベストのうち最も新しい日）で計算。平均行・カテゴリー別平均・CSVにも含む。選手の入力欄は増えない
  - フィジカルのランキング：ON の項目は「項目名体重比」も選べる（大きい順。体重が分からない選手は除外）。元の項目のランキングでも数値の横に（1.88倍）のように併記。Big3合計の体重比を ON にした場合は、以前からの「体重比（Big3合計÷最新の体重）」ボタンは出さない
  - フィジカルの自己ベスト一覧にも体重比の列。選手の詳細画面に「項目名体重比の推移」グラフ（記録ごとに、その日時点の体重で割る）
- 選手一覧の最下行「平均」：表示中（学年・FW/BK で絞り込んだ後）の選手のうち、数値が入っている人だけで平均（小数第1位）。全員未入力なら「—」。CSV の最後の行は全選手の平均
- カテゴリー別の比較：カテゴリーで絞り込んでいないとき、表示中の選手に1人でもカテゴリー設定があれば「レギュラー平均」「その他平均（レギュラー以外。ベンチ・ベンチ外・未設定）」の行を追加。CSV にも同じ行（全選手が対象）
- 体重・Big3も項目設定の項目（key 付き）。値は今までどおり「毎日の記録」「測定のBig3入力」を使い、測定画面に別の入力欄は出さない。項目を削除しても記録は消えない（表示から外れるだけ）
- 単位が空欄または「なし」の項目は、単位を表示しない（見出し・CSV・入力画面とも）
- FW / BK はポジションから自動判定（データベースには保存しない）：PR・HO・LO・FL・No.8（と以前の「フロント」「バックロー」）→ FW、SH・SO・CTB・WTB・FB（と以前の「バックス」）→ BK

## 4. 権限（RLS）

- メンバーは全員分の記録を閲覧できる（ランキング・コーチ画面のため）
- 記録の追加・修正は本人分のみ
- 測定項目（`metrics`）・設定（`app_settings`）・練習日（`practice_days`）の変更はコーチのみ（データベースの権限 `is_coach()` で確認）
- メンバー追加・編集・並び替え・削除はコーチのみ（サーバー側 `app/api/admin/route.ts` で確認）
- 選手のログインは、サーバー側で名前から本人を探し、使い捨てのログイン用の鍵を発行して行う（メールは送らない）。合言葉がないため、名前を選べば誰でもその選手としてログインできる点に注意
